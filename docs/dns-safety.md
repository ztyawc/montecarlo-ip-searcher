DNS 更新流程如下：

1. 扫描前检查 DNS 本地配置、上传数量、超时和输出格式。上传候选从全部探测与下载均成功的结果中按下载速度排序后限额，包含顺序测速的后续成功项。
2. 先输出或保存扫描结果，检查编码、写入及文件关闭错误，成功后才开始 DNS 更新。有候选时，DNS 错误、超时或取消会返回退出码 1，已经保存的结果保留；没有成功候选则正常跳过。
3. 完整读取指定名称的现有 A/AAAA 记录及分页信息，保留已有的相同 IP，只处理本次候选涉及的地址族。只上传 IPv4 时，原 AAAA 不进入删除计划；其他名称和记录类型也不受本次清理影响。
4. 先创建缺少的记录，再重新读取并确认所有目标 IP、新记录 ID 及旧记录属性。发现并发新增的额外同族记录或旧记录变化时，停止清理。确认后只删除初始快照中计划移除的记录 ID，并检查最终结果。
5. 删除或最终检查失败时，重新读取实际状态，尝试恢复已删除旧记录的 IP 和属性。即使服务端完成删除但响应丢失，也会检查本次删除尝试；恢复时保留新增 IP。恢复不完整会明确报错。

保留的同 IP 记录继续使用原 TTL、代理等属性。恢复使用快照中的 TTL、注释，以及服务商支持的代理、标签、设置等属性，但重新创建的记录 ID 会变化。全新 Cloudflare 记录默认自动 TTL（`1`）、关闭代理；全新 Vercel 记录默认 TTL `60` 秒。

Cloudflare 使用精确名称过滤和页码分页，并校验返回的总数；Vercel 使用 v5 列表接口及数字游标。分页信息不足以确认完整性、重复、未前进或返回内容与声明矛盾时会报错。HTTP 请求拒绝重定向、非 2xx 状态及不完整的响应对象，响应体上限为 4 MiB。

| 期限 | 行为 |
| --- | --- |
| `--dns-timeout`，默认 `60s` | 从结果输出完成后开始，覆盖本次 DNS 操作及失败恢复 |
| 单个 HTTP 请求，`10s` | 包括建立连接、等待响应和读取响应体 |
| 恢复预留时间 | 上传开始时预留剩余时间的四分之一，最多 15 秒；正常更新使用余下时间 |
| 外部期限或用户取消 | 优先服从调用方的更短期限和取消信号，取消后不在后台继续恢复 |

恢复是有期限的尽力操作。创建部分成功后发生故障，旧记录与已创建的新记录会同时保留；恢复也可能因服务商不可用、并发改动或剩余时间不足而失败。DNS 服务商不提供本流程的跨请求事务，不能保证任意并发修改下的原子替换或全球解析同时生效。错误信息需要结合服务商当前记录判断，程序不会对结果不明的写入盲目重试。

配套的结果输出调整修复了审计第 3 项中的无效格式截断及 `debug` 编码错误漏报。普通文件仍直接写入，尚未实现“临时文件写完后原子替换”；磁盘故障时不能保证原输出文件完整。
